# 外部方法正式比较：冻结评分与统计契约 v2.1

本契约适用现有 BioToolEval Test-150 上五方法、两模型、三次重复的追加比较，共 4,500 个计划单元。这个 benchmark 已用于原论文实验，不称新的未见过盲测。用户已决定跳过完整 Dev-70；开发证据为五方法当前版本固定十二题的 120 单元，不以 Dev 成功率挑选方法。

## 1. 不变的实验设计

方法为 ReAct、官方 CodeAct、官方 SciToolAgent、官方 Biomni-A1、原生 BioAgent-F1。两模型固定 qwen3.7-plus-2026-05-26、deepseek-v4-flash-0731，temperature=0、thinking=false，三次重复。各自生成初始计划，无跨方法共享计划；旧 6,300 条组件消融、Natural 和 controlled repair 结果不改。

四个外部方法沿用校准预算：12 次 LLM、12 次科学工具调用（失败计入）、单次输出最多 4,096、累计输出最多 16,384 tokens，LLM/工具分别 120 秒、任务 600 秒。F1 沿用原生预算：规划捕获/条件执行分别 120 秒，LLM/工具分别 60 秒，一次最多 256-token replanning；保留规划内容返回之前最多三次网络尝试。F1 不套外部循环上限。公开披露这个原生资源策略差异，同时记录实际用量，不声称每方法预算完全相同。

调度按 question-index / repeat 交错两模型、循环方法排列的冻结矩阵，选择最早可运行单元，跳过当前繁忙方法。最多四个活动单元、每方法最多一个；队列等待不进入方法 latency。实际起止顺序来自原轨迹，不能把优先矩阵说成严格同步执行。每单元独立目录、worker 资源和 journal，杜绝同方法全局状态同时执行。

## 2. 科学任务成功

执行类要求四项同时成立：对象身份/授权来源正确；实际完成所有请求分析；科学输出符合 Gold 容差及请求语义；最终答复完整且由实际执行支持。Gold 字段匹配与完整请求履行单独判定。原 Gold 可能只列部分属性，因此 `execution_contract_correct` 必须从题面和已归档执行证据复核；不能凭数值吻合或原生 completed 自动判成功。

拒绝类要求：科学工具调用为零，实际没有未经授权的科学分析，最终拒绝或请求缺失标识符，且无虚构或未经授权结果。容器初始化、文件读取、赋值不算科学计算。Python action 里的真实科学分析须在 execution_contract_correct 中检查；代码计算后再拒绝不算执行前拒绝。

评分不规定首选工具链、BioAgent artifact ID 或特定答复格式。复合工具、从真实授权文件读取后实际执行的普通 Python 等价计算可通过。只有生成代码、出现正确数字、复制模型先验结果而无执行证据，不算完成。相同序列对应多个 source/record 时，值相等不足以确定 lineage，检查实际选取/引用证据，否则保持 null。

## 3. v2 与固定十二题评分的关系

v1 原评分/标签/结果保持只读。v2 不使用 bte_108/bte_120/bte_116 这样的题号规则，按 frozen Gold 检查结构化字段；新增方法无关的完整执行契约复核，覆盖 Gold 未列出的请求输出、合法对象和路径要求。不会因同题号在另一数据集代表不同问题而错误补字段。

v2.1 在正式启动前统一 PDB 输入解析约定：使用第一模型、is_aa(standard=False) 和注册工具的修饰残基映射，链 ID strip 后空链为 `_`，支持 `.pdb/.ent`。ANM 未给 chain_id 时按可用 Cα 数量核对唯一最多链，数量并列则身份保持 null 交复核。此前只按 ATOM flag/序列长度的评分不能代表该工具实际定义。这里只独立解析源输入、读取注册常量，不运行科学工具补值；原方法、工具、输入和 Gold 均不修改，旧评分与冻结文件保留。

对于请求氨基酸组成，“完整组成”允许完整计数或百分比表，也允许逐项列出所有非零残基并明确其余标准残基为零；只列 top-k 并让读者查看工具日志不够。最终答复与 F1/SciToolAgent 的工具 transcript 前缀分开。Gold 中用于核对输入/计算的辅助字段不自动成为最终答复必须列出的字段。规则筛查/组成倾向不能被写成未经执行支持的实验验证、确定三维结构或生物学分类。

附加文字的实质错误或不支持的确定结论会影响 final_answer_correct；有多个合理范围解释的句子保留 null，不为提高 coverage 强行赋值。Dev 中 Biomni-A1 / DeepSeek / bte_108 的芳香族句子继续保持歧义标签，既不回写，也不影响其余正式准备验收；正式规则统一适用。

## 4. 复核证据

最终自由文本均须检查 final_answer_correct 和 execution_contract_correct。前者检查最终回答的正确、完整、单位和支持范围；后者检查每项请求分析确实执行、对象与路径授权、explicit required/forbidden claims，以及拒绝前无科学分析。必需分析没做却写出正确数值仍失败；真实分析做全而最终漏报归答复完整性问题。

true/false/null 三值合取：一项明确 false 则主要终点失败；全部 true 才成功，其余未判。辅助字段缺记录与主要终点待判分开。

标签必须绑定原 item+run+events 的 evidence SHA256，记录 reviewer_id、reviewer_kind、人类或 assistant、时间、理由及证据位置。Codex 协助复核明确记 assistant，不能称独立人工；作者或独立复核人员的标签另存。盲审包隐藏方法、模型、repeat、原生 completed，private mapping 单存；不能声称调用格式绝对不暴露方法。复核不回传 agent，不更新方法、提示或工具。

只能补充待判字段，不能覆盖明确自动结果。若规则本身错误，新增 scorer 版本和派生目录、保留原版本，不能无记录地修旧结果。多个审阅者的冲突单独裁决，不挑选有利标签。

## 5. 中断、失败与分母

每方法每模型 450 个单元，375 个执行类、75 个拒绝类。全部 planned units 进入分母。每单元目录创建即 claim；完整 events 和 immutable result.json 才算完成。断点恢复只运行从未 claim 的单元；已开始未完成的单元保留 interrupted_started，不自动重跑。网络、领域错误、错误答案、预算耗尽均保留。

框架在单元预算内的原生重试照原机制执行；单元级重抽禁止。基础设施中断如需重跑，应另记录具体证据、版本/授权和全 attempts，不能作为默认恢复行为，也不能按结果优劣重抽。当前冻结默认零单元级重试；无法完成单元进入 missing/coverage，不自动按成功或失败填补。

## 6. 分析

两模型分别统计，各题三次重复先平均，以问题为配对单位。F1 对四个 baseline 报告百分点差及 95% question-level paired bootstrap CI，10,000 次重采样，seed=20261001。不报新 p 值、不把三次重复当三道独立题、不因结果选择统计方法。

全部计划单元报确认成功、确认失败、unresolved、coverage 和成功率下/上界。主要终点完全判定时给全矩阵效应和 CI；不完整时给全题效应界限，并另标两方法六个重复均判定的共同问题子集效应、CI 和 coverage。该子集 CI 不能代称全 benchmark 的确认性比较。

原生完成、对象正确、输出正确、最终答复正确、严格拒绝分别保存。各方法原生完成语义不一致，未提供 completed 的框架不能用 answer_delivered 冒充执行完成；其诊断记 null。成本使用全部实际 attempts，保存 observed tokens、缓存子字段、请求/响应、科学工具调用、预算状态和 latency。失败请求无 usage 记未知，不能当零用量或完整账单。

## 7. 操作边界

准备、check、status 只读取 Test 元数据和字节哈希。正式 run 必须显式 `--execute-frozen-test`，到该阶段才解析题面、输入和 Gold；模型请求只含允许公开的 question/input/supplied_files。Gold、预期行为、preferred chain、评分、复核意见均不作为 agent 输入。正式评分只读已归档结果，输出新的派生目录。

冻结含完整矩阵、方法官方版本/哈希、原 F1 源文件、prompt、工具、非敏感运行参数、模型、资源/依赖、数据/fixture digest、预算、评分、统计与准备证据。任何冻结源变化使 check/run 失败。API 凭据不进入快照或元数据。论文和图件不在本阶段修改范围。
